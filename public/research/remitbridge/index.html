01 — Product Vision

What are we building and why

RemitBridge is a cross-border remittance middleware platform. We sit between banks and fintech apps in different countries, making it instant, transparent, and fair to send money across borders — starting with Saudi Arabia to Nigeria and expanding from there.

The one-sentence pitch: We are the invisible infrastructure layer that lets someone in Saudi Arabia open their bank app, send money to Nigeria, and have their family receive it instantly — with a fair exchange rate shown upfront, no hidden fees, no agents taking a cut.
What we ARE

A Middleware Platform

We don't hold money. We don't need a banking license. We are a technology layer that orchestrates instructions between licensed banks and licensed fintechs in each country. Our value is speed, transparency, and the corridor connection that doesn't exist today.

What we are NOT

Not a Bank or Wallet

We do not store customer funds. We do not issue cards. We are not a payment service provider. This keeps our regulatory footprint lean. The banks and fintechs we connect to hold the licenses — we connect them via API.

Our revenue model

FX Spread + Transaction Fee

We earn on the difference between the rate we get from the FX feed and the rate we show the customer (our spread, e.g. 0.5–1.5%). We can also charge a flat per-transaction fee. Both are shown transparently on the confirmation screen.

Who we serve

Migrant Workers & Pilgrims

Nigerians working or travelling in Saudi Arabia. Eventually: any African diaspora worker in the Gulf. Also businesses paying suppliers, and travel agents handling group Hajj/Umrah remittances at scale.

02 — Core Features

What the system must do

Every feature below is a required capability of the platform — not optional extras. This is the minimum viable product that makes the business model work.

Feature F-01

User Registration & KYC

Collect identity documents, selfie, phone number, and country of residence. Verify against government ID databases automatically.

Feature F-02

Live FX Rate Display

Show the real-time exchange rate pulled from a global FX feed before the user commits. Rate locked for 60 seconds once they confirm.

Feature F-03

Send Money (Outbound)

User enters recipient account/wallet, amount in SAR. System shows NGN equivalent, fee breakdown. One-tap confirm to execute.

Feature F-04

Instant Recipient Credit

Payout hits the Nigerian fintech (OPay / Kuda / Moniepoint) within seconds of confirmation. Recipient gets SMS + in-app notification.

Feature F-05

Transaction History

Full audit trail per user — every send, every rate, every fee. Downloadable receipts. Useful for tax purposes and trust-building.

Feature F-06

Beneficiary Management

Save frequent recipients (name, account number, bank/wallet). One-tap resend to a saved beneficiary.

Feature F-07

Multi-Channel Notifications

SMS + push notification at each stage: debit confirmed, transfer in progress, credit delivered. Sender and recipient both notified.

Feature F-08

Admin Dashboard

Internal ops panel: view all transactions, flag suspicious activity, manually resolve failed payments, run month-end reconciliation reports.

Feature F-09

Month-End Reconciliation

Automated generation of NIBSS-compatible batch settlement files. Exportable ledger reports per corridor per period.

04 — User Journey

Send Money Flow — Step by Step

This is the core transaction journey. The user experience must be fast, clear, and confidence-building. Rate shown. Fees shown. Recipient confirmed. One tap to send.

1

Tap "Send Money" on dashboard

User lands on the Send screen. Two fields: "You send" (in their local currency, e.g. SAR) and "They receive" (in the destination currency, e.g. NGN). Both update in real time as the user types.

2

Live rate displayed immediately

As soon as the user types an amount, the system pulls the live FX rate from our FX feed and shows: the rate, our fee, and the exact amount the recipient will receive. No surprises at the end.

XE APIOpen Exchange Rates
3

Select or add recipient

User picks from saved beneficiaries (name + account) or adds a new one. For Nigeria: enter 10-digit NUBAN account number, select bank or OPay/Kuda wallet. Account name is looked up automatically via the Nigeria bank name enquiry API.

Flutterwave Name EnquiryOPay / Kuda API
4

Review & Confirm screen

Full summary shown: amount sent, fee, rate, recipient name, expected arrival. User has 60 seconds to confirm before the rate expires. A countdown timer is visible. If it expires, a fresh rate is fetched automatically.

5

PIN / Biometric authentication

Before executing, user must authenticate via PIN or biometric. This is the security gate. A transaction cannot proceed without this — preventing accidental or fraudulent sends.

6

Transaction executes in the background

Our middleware: (a) locks the FX rate, (b) debits the sender via the Saudi bank API, (c) fires a credit instruction to OPay/Kuda Nigeria. The user sees a loading state for 3–8 seconds while this happens.

Saudi Bank APIOPay APIKuda API
7

Success confirmation + notification

App shows a success screen with a receipt. Sender gets an in-app notification and SMS. Recipient (in Nigeria) gets an SMS from OPay/Kuda saying their account has been credited — along with who sent it.

Firebase PushTermii SMS

05 — User Journey

Receive Money Flow

The recipient (in Nigeria or another destination country) does not need to be a RemitBridge user to receive money. They just need an OPay, Kuda, or bank account. However, if they ARE a RemitBridge user, they get richer notifications and can initiate a return transfer easily.

Non-RemitBridge recipient

Receiving via OPay / Kuda / Bank

Recipient already has an OPay or Kuda wallet or any Nigerian bank account. The sender provides the account number. Money arrives in the recipient's existing account automatically — no action needed from the recipient. They receive an SMS credit alert from their bank/wallet provider.

RemitBridge recipient

Receiving via RemitBridge App

If the recipient also has RemitBridge installed, they see the incoming transfer in real time on their dashboard. They can tap to see the full receipt: who sent, how much in the source currency, the rate applied, and the NGN amount credited to their linked account.

Future feature (Phase 2): Recipient Request Link — a recipient in Nigeria can generate a payment request link (like a payment invoice) and send it to someone in Saudi Arabia. The sender clicks the link, authenticates in the app, and the transfer executes with the recipient's details pre-filled. Great for recurring family remittances.

08 — Core Engine

Transaction Engine — States & Logic

Every transaction moves through a defined set of states. The engine must be fault-tolerant — if any step fails, it knows exactly where to resume, retry, or rollback. No money can be debited without a matching credit, and no credit is issued before a debit is confirmed.

stateDiagram-v2 [*] --> INITIATED: User confirms transfer INITIATED --> RATE_LOCKED: FX rate locked for 60s RATE_LOCKED --> DEBIT_PENDING: Bank debit instruction sent RATE_LOCKED --> EXPIRED: 60s elapsed — user must retry DEBIT_PENDING --> DEBIT_CONFIRMED: Bank webhook confirms debit ✅ DEBIT_PENDING --> DEBIT_FAILED: Bank rejects (insufficient funds / error) DEBIT_FAILED --> FAILED: No money moved — safe to abandon DEBIT_CONFIRMED --> CREDIT_PENDING: OPay/Kuda credit instruction sent CREDIT_PENDING --> CREDIT_CONFIRMED: Fintech webhook confirms credit ✅ CREDIT_PENDING --> CREDIT_RETRY: Credit failed — auto-retry (3x) CREDIT_RETRY --> CREDIT_PENDING: Retry attempt CREDIT_RETRY --> MANUAL_REVIEW: All retries exhausted CREDIT_CONFIRMED --> SETTLED: Record archived ✅ Notifications sent MANUAL_REVIEW --> CREDIT_PENDING: Ops team manually re-triggers MANUAL_REVIEW --> REFUND_PENDING: Ops decides to refund sender REFUND_PENDING --> REFUNDED: Bank credits sender back SETTLED --> [*] FAILED --> [*] REFUNDED --> [*] EXPIRED --> [*]
Critical rule — no orphaned debits: If a debit is confirmed but credit fails 3 times and goes to manual review, the system holds the debited SAR in a suspense ledger. Ops can see this immediately in the admin dashboard. The customer is notified that their transfer is being manually processed and will either complete or be refunded within 24 hours. Zero silent failures.
09 — Security & Compliance

How we keep user data and money safe

Operating a financial platform means we are a target. Security is not optional — it is baked into every layer of the architecture from day one.

Authentication

JWT + Biometric Auth

Short-lived JWT access tokens (15 mins) + long-lived refresh tokens stored securely on device. All transactions require re-authentication via PIN or biometric. No transaction executes without user intent confirmation.

Data Encryption

Encryption at Rest & Transit

All data encrypted at rest (AES-256 via AWS KMS). All API communication over TLS 1.3. KYC documents (ID images, selfies) stored in encrypted S3 with strict IAM policies — not accessible to any application service, only to the KYC pipeline.

Fraud Prevention

Rate Limits + Velocity Checks

API rate limiting per user per minute. Velocity rules: flag if a user attempts more than N transactions in 24h, or if the total value exceeds their tier limit. Rules are configurable in the admin dashboard without a code deploy.

Transaction Limits

Tiered Sending Limits

Tier 1 (phone only): up to $200/month. Tier 2 (KYC verified): up to $5,000/month. Tier 3 (enhanced KYC + source of funds): unlimited. Users are prompted to upgrade tiers inline when they approach their limit.

Audit Trail

Immutable Event Log

Every action — login, transaction attempt, KYC update, admin override — is written to an append-only audit log. This log cannot be deleted or modified. It is the source of truth for dispute resolution and regulatory reporting.

Regulatory

AML Monitoring

Ongoing transaction monitoring via ComplyAdvantage. Suspicious activity reports (SARs) generated automatically when rules are triggered. Monthly reporting to relevant financial intelligence units as required by law in each operating country.
